# 日本株スクリーニング・バックテスト

J-Quants API V2の日足を使い、勢い重視のスクリーニング条件を評価します。LLM・Kronos・発注機能はありません。シグナル単位の成績に加え、初期資金10万円で「100株単位」と「単元未満株」を比較します。

## セットアップ

Python 3.10以上を使います。

```bash
cd ai-analyst/jp-stock-backtest
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

J-Quantsのダッシュボードで発行したV2 APIキーを環境変数に設定します。キーはファイルやコマンド履歴に書かず、リポジトリにもコミットしないでください。

```bash
export JQUANTS_API_KEY='発行したAPIキー'
python backtest.py --config config.yaml
```

Freeプランは5リクエスト/分のため、初期設定ではAPIリクエスト間を12.1秒空け、HTTP 429/5xxを指数バックオフで再試行します。キーが未設定の場合、APIアクセス前にエラーになります。テストはネットワーク接続やAPIキーを必要としません。

## データと設定

V2の `x-api-key` ヘッダーを使い、`/markets/calendar` で取引日、`/equities/bars/daily?date=YYYYMMDD` で日付ごとの全銘柄日足を取得します。レスポンスの `pagination_key` がなくなるまでページを取得します。OHLCVは `AdjO` / `AdjH` / `AdjL` / `AdjC` / `AdjVo`、売買代金は `Va`、上限到達フラグは `UL` を使用します。日足は日付ごと、上場銘柄マスタは各月の最初の営業日ごとにParquetへ保存し、既存日付は再取得しません。マスタの `ProdCat` と `Mkt`、普通株を示すコード末尾を使って対象を絞ります。過去データの上場銘柄を日付単位で取得するため、現在の上場銘柄一覧だけで過去銘柄を絞り込むことはありません。

`config.yaml` で期間、閾値、上位N、評価日数、資金、コスト、税率、キャッシュ先を変更できます。初期期間はFreeプランの範囲に合わせ、データ取得終了日を実行日から84日前、開始日をそこから2年前に設定します。`start_date` / `end_date` を指定すると期間を上書きできます。期間指定がプランの利用可能範囲外の場合はAPIがエラーを返すことがあります。

## 判定と評価方法

- シグナル日は当日終値までで判定します。20日高値は当日を含まず、`t-20`〜`t-1` の高値の最大です。移動平均、20日平均売買代金は当日を含みます。出来高倍率の分母は当日を除く過去20営業日平均です。
- 条件は20日平均売買代金5億円以上、出来高倍率2.0以上、20日高値ブレイク、終値 > 25日線 > 75日線、25日線乖離率+25%以下です。
- 各月の最初の営業日に取得した `/equities/master` をコードで統合し、最新スナップショットを使います。`ProdCat=011`かつコード末尾が`0`の国内普通株を対象にし、ETF/REIT等の他商品区分と`Mkt=0105`（TOKYO PRO Market）を除外します。全スナップショットにないコードは保持し、件数を`summary.md`に記載します。
- シグナル銘柄は日ごとに出来高倍率とブレイク幅の百分位順位を平均し、52週高値更新に設定値（初期値0.1）を加点したスコアで並べます。上位100・10・30銘柄を比較します。
- エントリーは翌営業日始値、決済はエントリー日を1日目とする3・5営業日目（`t+N`）の終値です。MAEはエントリー日から決済日までの安値で算出します。流動性・出来高・ブレイク・移動平均に必要な75営業日（設定変更時は各条件の最大値）をウォームアップとして除外します。52週高値は過去250営業日の高値が揃ってから判定し、それ以前はボーナスを付けません。
- シグナル単位のリターンは1株を想定し、往復コストをエントリー・決済各半分として控除します。ベンチマークは、シグナル日の流動性条件を満たした銘柄の同期間リターン平均です。粗超過リターン（コスト前）とコスト後超過リターン（コスト後シグナル−同じベンチマーク）を両方表示します。
- ポートフォリオAは翌日始値で一銘柄につき100株（一単元）を購入し、コスト込みで現金を超える候補はスキップして次の銘柄に進みます。Bは1株単位で、最大3銘柄を上限に空き枠で現金を均等配分します。保有期間中は資金を拘束し、同じ銘柄を重ねて買いません。資産は日々終値で評価します。
- ポートフォリオのベンチマークは、前営業日終値時点で流動性条件を満たす銘柄の終値間リターンを均等加重して複利運用します。損益は決済年ごとに通算し、黒字年に限り税率20.315%を適用します。

## 結果の読み方

- `output/signals.csv`: 条件値、スコア・日次順位、エントリー可否、3・5営業日リターン、MAEを銘柄・シグナル日ごとに出力します。
- `output/summary.md`: Top N × 保有日数の件数、勝率、平均・中央値リターン、MAE、粗・コスト後の超過リターン、月別成績、A/B/ベンチマークの最終資産・CAGR・最大ドローダウン・月別損益・税引後損益、Aの価格理由スキップ率、コスト感度、マスタ未登録コード数を表示します。
- `entry_excluded` は翌日始値欠損/0、出来高欠損/0、または`UL=1`かつ始値=高値の候補の除外数です。`horizon_excluded` は期間末で`t+N`まで評価できない候補数、`決済価格なし`は予定決済日の終値を取得できない数です。

## 制約事項

- Freeプランの株価は過去2年分・12週間遅延です。日付指定により上場廃止銘柄を取得できる場合がありますが、保存期間やデータ欠損のため完全な上場廃止銘柄カバレッジは保証できません。API対象は東証上場銘柄です。
- J-Quants V2は株式分割等で調整後価格を遡及再計算します。調整後価格を使う指定に従いますが、当時取得できた価格に固定されたポイントインタイムデータではありません。また、現金配当調整は含まれません。
- Freeプランの日足には前場・後場別データがありません。単元未満株の証券会社ごとの約定タイミングを再現せず、翌営業日始値で近似しています。
- `UL` は当日高値が上限に達したかを表し、始値が上限だったかは単独では識別できません。翌日`UL=1`かつ始値=高値の場合だけ除外し、`UL=1`でも始値が高値未満ならエントリー可能とします。
- J-Quants V2の`ProdCat`でETF/REIT等、`Mkt`でTOKYO PRO Marketを識別できます。`ProdCat=011`には優先株等も含まれるため、普通株コード末尾`0`も使います。商品区分にはETN・インフラファンドを直接示す区分がないため、これらが国内普通株として記録された場合は識別できず残る可能性があります。
- 全マスタスナップショットにないコードは保持します。マスタの分類情報がないため、該当コードに非普通株が含まれる可能性があります。
- 税計算は決済年の実現損益のみで、翌年以降への損失繰越は行いません。未決済建玉の含み益は課税対象外です。
- 価格欠損などで予定決済日に売却できない建玉は、価格を再取得できる日まで保有し、期間末時点では最終取得終値で評価します。

Freeプランの初回フル実行はカレンダー約1回、日足約490回、月次マスタ約24回のリクエストが必要です。12.1秒のレート間隔で概ね1.5〜2時間かかります（ページングや再試行を除く）。再実行では日足・マスタのキャッシュを使い、取得済み日付を再取得しません。
