# FX短期ブレイクアウト・バックテスト（AI-239）

## 目的と対象範囲

このスクリプトは、短期ブレイクアウト条件の過去データ検証を行います。AI-239の検証用ツールであり、LLMやKronosは使用しません。実際の注文・発注機能はなく、バックテストのみを実行します。結果は将来の成績を保証するものではありません。

## データソースと利用上の注意

- データソースはDukascopyの過去データです。`https://datafeed.dukascopy.com/datafeed` から通貨ペアごとの1時間足BIDデータ（`.bi5`）を取得します。
- 公開エンドポイントはレート制限が厳しく、HTTP 429（Too Many Requests）・503・タイムアウトが頻繁に返ります。取得層はリクエスト間隔（`data.request_interval_sec`）を空け、指数バックオフで再試行し、取得済みの月はキャッシュから読むため、途中で失敗しても再実行すれば続きから取得します。初回の全期間取得には1時間程度かかることがあります。
- APIキーは不要です。
- 利用は個人・非商用に限り、取得データの再配布は禁止されています。`data/`には取得データとローカルキャッシュ、`output/`には検証結果を保存します。どちらもGit管理対象外です。データや出力ファイルを公開・配布しないでください。
- 設定ファイルの`data.start`から月単位で取得し、完了済み月はParquet形式でキャッシュします。実行中の月は未完了としてキャッシュしません。

## セットアップと実行

このディレクトリで実行してください。

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
. .venv/bin/activate
python fx_backtest.py --config fx_config.yaml
```

実行後、設定の`data.cache_dir`にデータキャッシュを、`output.dir`に結果ファイルを保存します。標準の設定では、それぞれ`data/`と`output/`です。

## 日足の定義

- Dukascopyの1時間足を`data.day_boundary_tz`（既定値：`America/New_York`）に変換し、NY時間17:00（`data.day_boundary_hour`）で区切ります。夏時間はIANAタイムゾーンに従って自動的に切り替わります。
- 日足ラベルはセッション終了日の暦日です。週末の日付としてラベルされた日足は除外します。日曜夕方から始まり月曜17時に終わるセッションは月曜日のラベルになります。
- 出来高が0の時間足は日足の集計前に除外します。日足の始値・高値・安値・終値は、残った時間足の最初の始値・最高値・最安値・最後の終値です。

## シグナルとトレード評価

- 買いは、当日終値が前日までの20日高値を上回り、終値 > 25日移動平均 > 75日移動平均となる場合です。売りは、当日終値が前日までの20日安値を下回り、終値 < 25日移動平均 < 75日移動平均となる場合です。期間と売買方向の有効・無効は設定で変更できます。
- ブレイクアウト高値・安値は「前日までの20日高値」= t-20〜t-1の高値の最大値として計算し、シグナル日tの高値・安値は含めません。移動平均はシグナル日tの終値を含みます。ATRはWilder方式です。シグナルはtの終値までの情報だけで判定します。
- 当日値幅がATR×設定値を超える日は過熱として除外します。
- 保有日数の定義：シグナル日 t（t の終値までで判定）→ t+1 の始値でエントリー → エントリー日を保有1日目として N 営業日目（= t+N）の終値でエグジット。N=3 なら t+3 の終値。最大逆行は t+1〜t+N の安値（売りは高値）基準。
- 買いはBID足の始値にスプレッドを加えた価格で入り、BID価格で決済します。売りはBID価格で入り、決済時にスプレッドを加えたASK価格で買い戻します。スプレッドは通貨ペア別の設定値です。
- 損切り幅はシグナル日ATR×`exit.stop_atr_mult`です。日中に損切り価格へ達した場合は損切り価格で決済し、エントリー日より後の日に始値が損切り価格を越えて窓を開けた場合はその始値で決済します。任意の利確価格を設定した場合も、後日の始値が利確価格を越えればその始値で決済します。同じ日足の中で損切りと利確の両方に達した場合は、保守的に損切りを優先します。
- スワップは通貨ペア・売買方向ごとの仮値を保有日数分加算します。水曜日（曜日番号2）は3日分として数えます。固定の概算値であり、実際の金利・業者条件の変動は反映しません。レポートにはスワップ込み・除く資金シミュレーションを出力します。
- 前半・後半の境界は`split.split_date`で指定できます。`null`の場合は全データ期間の中間日を境界にし、その日以降を後半に分類します。前半は条件調整用、後半は検証用で、レポートの「主結果」は後半です。
- ランダムベンチマークは、同じ通貨ペア・売買方向ごとにルールと同じ件数を候補期間から復元抽出し、同じ保有日数・損切り・コスト条件で比較します。乱数seedは`benchmark.seed`、試行回数は`benchmark.n_runs`です。p値は「ランダム試行の平均損益がルールの平均損益以上となった割合」に+1補正を加えた値（回数+1で除算）です。

## 資金シミュレーション

- 初期資金と1回あたりの許容損失率は設定可能です。サイズは損切り時のリスクから算出した数量と、実効レバレッジ上限から算出した数量の小さい方を最小取引単位で切り下げます。
- 実効レバレッジの上限は既定で1倍です。上限計算では、買いの想定元本に加え、売りは損切り幅の2倍を加えた必要額を見積もります。窓開け損失や円換算レート変動などにより日次評価で上限を超えた場合は、安全装置として全ポジションを同じ比率で縮小します。
- 同時保有は既定で最大3件、同一通貨ペアは1件です。`max_positions_per_currency`を指定すると、通貨ごとの保有制限も適用します。最小取引単位は1・100・1,000通貨を比較でき、見送り理由`max_positions`、`pair_held`、`currency_limit`、`unit_too_small`、`leverage_cap`ごとに件数を記録します。
- EURUSDなど決済通貨が円でないペアの損益・想定元本は、USDJPYの日足で円換算します。
- 税額は暦年ごとの実現損益を基に20.315%で概算します。損失は3年間繰り越して利益と相殺します。税額はシミュレーション上の推定であり、税務助言ではありません。

## 出力ファイル

すべて`output.dir`で指定したディレクトリに作成します。

| ファイル | 内容 |
| --- | --- |
| `fx_trades.csv` | ルールに合致した各トレード。期間、保有日数、シグナル・エントリー・決済日、通貨ペア、売買方向、価格、pips・円換算損益、最大逆行、決済理由など。 |
| `fx_summary.md` | 前半・後半別の成績、ランダム比較、資金シミュレーション、通貨ペア・方向・年別成績、データ品質の集計。最初の「主結果（後半・検証用）」を主要な検証結果として確認してください。 |
| `fx_equity.csv` | 後半・最小取引単位・スワップ込みを含む、資金シミュレーションの日次現金、資産、想定元本、実効レバレッジ、保有件数。 |
| `fx_portfolio_trades.csv` | 資金シミュレーション上の数量、円損益、決済理由を含むトレード明細。 |
| `fx_monthly.csv` | ルールによる月別の取引成績。 |

`fx_summary.md`では、まず後半の取引成績とランダムエントリー比較を確認し、次に最小取引単位での資産推移・最大ドローダウン・税引き後損益・実効レバレッジを確認してください。前半の結果は条件調整用であり、後半と区別して扱います。

## 設定項目

設定は`fx_config.yaml`にあります。相対パスは設定ファイルのあるディレクトリを基準に解決します。

| 項目 | 主なキー | 説明 |
| --- | --- | --- |
| データ取得 | `data.source`, `data.base_url`, `data.price_side` | データソース名、DukascopyのURL、価格側（既定値BID）。 |
| 取得期間・保存 | `data.start`, `data.end`, `data.cache_dir` | 開始月、終了月（`null`は直近の完了月）、キャッシュ先。 |
| 通信 | `data.request_interval_sec`, `data.max_retries`, `data.backoff_base_sec`, `data.timeout_sec` | リクエスト間隔、再試行回数、指数バックオフ基準、タイムアウト秒数。HTTP 429では数値の`Retry-After`も尊重します。 |
| 日足境界 | `data.day_boundary_tz`, `data.day_boundary_hour` | セッション境界のタイムゾーンと時刻。既定値はNY時間17時です。 |
| 対象ペア | `pairs`, `conversion_pair` | 検証する通貨ペアと、円換算に使うペア（既定値USDJPY）。 |
| シグナル | `signal.breakout_lookback`, `signal.ma_short`, `signal.ma_long`, `signal.atr_period` | 高値・安値ブレイク期間、短期・長期移動平均、ATR期間。 |
| シグナル制御 | `signal.overheat_atr_mult`, `signal.enable_long`, `signal.enable_short` | 過熱判定倍率、買い・売りシグナルの有効化。 |
| 決済 | `exit.holding_days`, `exit.stop_atr_mult`, `exit.take_profit_atr_mult` | 保有営業日数、損切りATR倍率、任意の利確ATR倍率（`null`は利確なし）。 |
| コスト | `costs.spread_pips`, `costs.swap_pips_per_day`, `costs.triple_swap_weekday` | ペア別スプレッド、方向別スワップ仮値、水曜の3日分計上に使う曜日番号。 |
| 期間分割 | `split.split_date` | 分割日。`null`は期間の中間日を使用します。 |
| ランダム比較 | `benchmark.n_runs`, `benchmark.seed`, `benchmark.alpha` | 試行回数、乱数seed、ランダムに勝ったと判定する有意水準。 |
| 資金管理 | `portfolio.initial_capital`, `portfolio.risk_per_trade`, `portfolio.max_leverage` | 初期資金、1回あたりのリスク率、実効レバレッジ上限。 |
| ポジション制限 | `portfolio.max_positions`, `portfolio.max_positions_per_pair`, `portfolio.max_positions_per_currency` | 全体・ペア別・通貨別の同時保有上限。通貨別上限の`null`は無効です。 |
| 数量・税 | `portfolio.min_units`, `portfolio.tax_rate`, `portfolio.tax_loss_carryforward_years` | 比較する最小単位、税率、損失繰越年数。 |
| 品質検査 | `quality.spike_zscore`, `quality.spike_window`, `quality.min_hours_per_day` | スパイク判定倍率・参照期間、短時間足日として記録する最低時間足数。 |
| 出力先 | `output.dir` | レポート・CSVの保存先。 |

## 制約

- スプレッドとスワップは設定内の仮値であり、実際の業者・時間帯・市場状況による変化を表現しません。手数料、スリッページ、約定拒否、流動性、レバレッジ金利もモデル化していません。
- 1時間足BIDデータから日足を生成するため、ティック単位の約定順序や日足内の価格経路は分かりません。同じ日足で損切りと利確の両方に達した場合は損切り優先とする保守的な仮定を置いています。
- 品質検査は欠損日、OHLC不整合、対数リターンのスパイクを記録するもので、データの補正・除外は行いません。
- 税額、円換算、資金・レバレッジ計算は設定と日足に基づく概算です。実運用や投資判断に使用する前提のシステムではありません。
- Dukascopyの利用条件に従い、ダウンロードしたデータやバックテスト出力を再配布・公開しないでください。
